# Anasym — дорожная карта до production

Дата аудита: 2026-11-08. Основа: состояние репозитория `kodyter-main` (локальная `main`, 11 коммитов впереди и 1 позади `origin/main`), код, конфигурация и результаты команд, запущенных в этот день.

**Метки:**
- **[факт]** — проверено командой или чтением кода. Ссылка на файл или вывод команды.
- **[не проверено]** — предположение или то, что требует доступа, которого у аудита нет (панель Supabase/Vercel, GitHub, Docker, реальные данные).

## 1. Общая оценка MVP

**Состояние: сильный MVP, не готов к приёму реальных заказов.**

Сильные стороны [факт]:
- Django 5.2 + DRF, PostgreSQL в проде, SQLite для разработки.
- Серверная защита цен, идемпотентность заказов, блокировки строк `select_for_update` на всех денежных и статусных операциях, снимки позиций заказа.
- `manage.py makemigrations --check` — изменений нет. `manage.py check --deploy` в production-подобном окружении — без замечаний.
- Тесты: Django — 156, `OK (skipped=12)`; фронтенд — 26/26.
- Продуманная модель ролей: покупатель, администратор, курьер, кассир. Права проверяются на сервере.

Слабые места [факт]:
- История git не синхронизирована с GitHub: конфликты в 6 файлах (см. P0-01).
- Тесты на параллельность (12 шт.) никогда не выполнялись на PostgreSQL: локально пропускаются.
- Есть реальная утечка внутренних полей заказа покупателю (P0-02).
- Контактные данные на сайте — заглушки (P0-05). Все коммерческие данные по `docs/implementation-plan.md` — демонстрационные.
- Нет мониторинга ошибок: единственное логирование — `logger.exception` в `auth_views.py`. Sentry и настроек логов нет.
- Нет E2E-тестов. Фронтенд тестируется только `node:test`.

**Не проверено:** состояние продакшн-базы Supabase, наличие и частота бэкапов, факт деплоя на Vercel, работа Docker-стека (Docker Desktop не запущен), реальная нагрузка.

## 2. Реализованный функционал [факт]

**Бэкенд** (`backend/shop/`): 8 моделей (`User`, `Category`, `Product`, `Order`, `OrderItem`, `StatusHistory`, `Problem`, `Payment`) и 31 эндпоинт в `shop/urls.py`:
- Аутентификация: CSRF, регистрация, вход, выход, профиль, сброс пароля (ссылка действует 1 час, `PASSWORD_RESET_TIMEOUT = 3600`).
- Каталог: категории, товары, поиск, карточка товара, настройки магазина (доставка 1500 ₸, оплата при получении).
- Заказы: оформление (идемпотентность по `idempotency_key` и отпечатку запроса), список с фильтрами (статус, дата, курьер, поиск по номеру и телефону), смена статуса по цепочке, назначение курьера, сообщение о проблеме.
- Курьер: пул свободных заказов, принятие заказа под блокировкой.
- Кассир: приём оплаты наличными один раз на заказ, сводка за день.
- Администратор: CRUD категорий и товаров (без удаления), управление курьерами и кассирами, сводка «требует внимания».

**Фронтенд** (`frontend/src/`): витрина (главная, каталог, карточка товара с пресетами количества), гостевая корзина в `localStorage`, оформление с проверкой цен на сервере, вход и сброс пароля, кабинеты покупателя / администратора / курьера / кассира (`Portals.tsx`), страницы «О нас», «Доставка», «Контакты», политика конфиденциальности и оферта, баннер cookies, карта Leaflet, три языка (қаз / рус / eng).

**Инфраструктура** [факт]: `docker-compose.yml` (PostgreSQL 17, Django под gunicorn, nginx), `deploy/` (nginx, Caddy, заголовки безопасности), `vercel.json` и `api/index.py` для Vercel, `scripts/` (launch, stop, backup, restore, setup-env под Windows), CI `.github/workflows/ci.yml` (локальный коммит, на GitHub ещё не отправлен).

## 3. Незавершённые функции [факт]

- Покупатель не может отменить заказ. Отмена — только у администратора (`Transition`, `CANCELLED`).
- Нет управления остатками: товар доступен или нет, количества нет.
- Нет онлайн-оплаты. Только наличные при получении.
- Нет подтверждения email при регистрации.
- Нет пагинации списков заказов для администратора (P1-04).
- Нет редактирования адреса доставки после оформления.
- Нет удаления товаров и категорий. Скрытие возможно через `is_visible` (API), но интерфейса для этого в админке не проверялось [не проверено].
- Нет экспорта отчётов (кассовые сводки только на экране).
- Нет E2E-тестов, нет мониторинга, нет алертов.

## 6. Архитектурные недостатки

- **Два источника правды для конфигурации.** `backend/.env.example`, `.env.example` в корне, `docker-compose.yml` и `deploy/` описывают одно и то же по-разному. Пример: `DEMO_MODE`, `COOKIE_SECURE`, `DATABASE_URL`.
- **Двойной путь БД.** Vercel использует `POSTGRES_URL`, Docker — `DATABASE_URL`, локально — SQLite. Поведение различается (`DatabaseCache` только на Vercel, `CONN_MAX_AGE` разный) [факт в `settings.py`].
- **Кэш на Vercel требует ручного `createcachetable`.** Без этого шага сессии/троттлинг могут падать [факт в `docs/vercel-deployment.md`; выполнен ли шаг в проде — [не проверено]].
- **Списки без пагинации.** `Orders.get` (APIView) возвращает все заказы. Пагинация opt-in через `?page_size` и не используется фронтендом [факт].
- **Монолитный `Portals.tsx`.** 58 КБ в 440 строках (длинные строки), четыре роли в одном файле.
- **Опрос каждые 5 с** для каждого открытого кабинета. Нагрузка растёт линейно с числом курьеров и кассиров [факт в коде; нагрузка [не проверено]].
- **Перегруженные сериализаторы.** `OrderSerializer` один для всех ролей. Причина SEC-01.
- **Блокировки в разных порядках.** Заказ, затем пользователь (`lock_active_actor`), в другом месте наоборот. Риск взаимоблокировок при параллельных запросах [не проверено на PostgreSQL].
- **Дубли тестов.** `shop/tests.py`, `test_regressions.py`, `test_staff_workflow.py` содержат похожие сценарии параллельности.

## 7. UI/UX и адаптивность

- **Контраст мелкого текста** (вычислено по WCAG 2.x): `.results-count` `#919082` — 2.91:1; `.product-weight` `#928368` — 3.35:1; `.breadcrumb` `#808572` — 3.44:1; `.eyebrow` `#7d775b` — 4.07:1. Требуется 4.5:1 для текста меньше 18pt.
- **Литералы вне i18n.** Грубая оценка по строкам с кириллицей: `Legal.tsx` ~92, `Portals.tsx` ~78, `App.tsx` ~17, `ShopFlow.tsx` ~10, `Home.tsx` ~9, `ui.tsx` ~8. Часть `Legal.tsx` — юридические тексты, которые могут быть только на русском по замыслу [не проверено]. Казахская версия интерфейса местами показывает русский текст.
- **Адаптивность проверена** на 360, 390, 768, 1366, 1920 px в `docs/` (отчёты 2026-10-16/17). После ноября 2026 не перепроверена [не проверено]. Сегодня проверены 1366 и 390 на 8 страницах: переполнения по горизонтали нет.
- **Исправлено 2026-11-07 (не закоммичено):** степпер количества на карточке товара растянулся до 396 px (стало 178 px); линия над нижней строкой футера выступала на 36 px; страница входа не доходила до низа экрана и заголовок упирался в край.
- **Hover-жирность меню** сдвигает соседние пункты на ~0.8 px. Незаметно, решено не трогать.
- **Баннер cookies** на мобильном закрывает часть экрана при первом входе. Допустимо, но не проверено на реальных устройствах.
- **Опасность блокировки ввода.** Пункт «`<` и `>` запрещены в свободном тексте» мешает вводу адреса и комментария с такими символами. Решение по UX нужно.

## 12. Backlog с приоритетами

**Приоритеты:**
- **P0** — блокирует запуск или ведёт к утечке/потере данных.
- **P1** — заметный дефект или риск до первых реальных клиентов.
- **P2** — качество и долг, не блокирует.
- **P3** — косметика и улучшения.

Формат каждой задачи: ID, описание, обоснование, затронутые файлы, риски, приёмка, тестирование.

### P0
