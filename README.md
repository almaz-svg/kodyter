## О проекте

Anasym — авторская кондитерская в Таразе (ул. Конаева, 62а). Покупатель выбирает товары в каталоге, оформляет доставку и платит при получении. Сотрудники работают в отдельных кабинетах: администратор управляет каталогом и заказами, курьер берёт заказы в доставку, кассир принимает оплату.

| Слой | Технологии |
| --- | --- |
| Фронтенд | React 19, TypeScript, Vite, React Router, Leaflet, lucide-react |
| Бэкенд | Django 5.2, Django REST Framework, Gunicorn |
| База данных | PostgreSQL 17 (рабочая и CI); SQLite — только для локальной разработки |
| Развёртывание | Vercel + Supabase (serverless) или Docker: Nginx и Caddy на собственном сервере |
| Языки интерфейса | қазақша, русский, English |
| Валюта | тенге (₸) |

> **Внимание.** Товары, цены, составы, контакты и учётные записи в начальном наполнении демонстрационные. Перед публичным запуском их нужно заменить (см. [Перед запуском](#перед-коммерческим-запуском)).

## Возможности

### Покупатель

- Каталог по категориям, страница товара с составом и аллергенами.
- Количество задаётся кнопками, вводом с клавиатуры или быстрыми значениями (10, 20, 50, 70).
- Корзина хранится в браузере; при входе и смене типа аккаунта цены в ней пересчитываются.
- Регистрация, вход, восстановление пароля, личные данные, история заказов.
- Оформление заказа с оплатой при получении. Итоговая сумма считается на сервере.
- Оптовые цены для одобренных заведений (см. [Ценообразование](#ценообразование)).
- Интерфейс на трёх языках, адаптивная вёрстка с мобильным меню и нижней панелью навигации.
- Карта с адресом, страницы «О нас», «Доставка», «Контакты», политика конфиденциальности, публичная оферта, баннер согласия на cookies.

### Персонал

| Роль | Раздел | Возможности |
| --- | --- | --- |
| Администратор | `/admin` | Каталог и категории, очередь заказов с фильтрами, смена статусов, назначение курьеров, управление курьерами и кассирами, одобрение заведений и оптовых цен |
| Курьер | `/courier` | Общая очередь свободных заказов, принятие заказа, свои доставки, сообщения о проблемах |
| Кассир | `/cashier` | Все заказы, состояние оплаты, приём наличных после доставки, сводка за день |
| Покупатель | `/account` | Свои заказы и личные данные |

Курьер видит в навигации только каталог и свой кабинет.

## Ценообразование

- **Розничная цена** действует для всех: гостей, физических лиц и заведений без одобрения.
- **Оптовая цена** задаётся администратором для каждого товара отдельно. Она не может быть выше розничной.
- **Условия оптовой цены:**
  1. аккаунт типа «Заведение» одобрен администратором (регистрация сама по себе оптовые цены не открывает);
  2. в одном заказе не меньше `WHOLESALE_MIN_QTY` штук (по умолчанию 10) **одного и того же товара**.
  Например, 10 круассанов считаются по оптовой цене, а 5 круассанов и 5 эклеров — по розничной, потому что ни одного товара не набрано до 10. Количества разных товаров не суммируются.
- **Подсказки.** Одобренное заведение видит оптовое предложение в каталоге и корзине: сколько добавить до порога и когда цена меняется.
- **Проверка на сервере.** Сервер сам определяет цену каждой позиции. Если цена в корзине не совпадает с серверной, заказ отклоняется с кодом 409, и покупатель видит просьбу обновить корзину.

## Безопасность

- Права проверяются на сервере. Скрытие разделов в интерфейсе не заменяет проверку в API.
- Сессии хранятся в cookie `HttpOnly`; изменяющие запросы требуют CSRF-токен.
- Ограничение частоты: 120 запросов в минуту для анонимных клиентов, 600 — для авторизованных, 60 в час — для входа, регистрации и восстановления пароля.
- Ссылки на фотографии принимаются только из `/images/`, `/media/` или с https-доменов из разрешённого списка. SVG запрещён.
- Свободный текст не принимает HTML-разметку (символы `<` и `>` отклоняются).
- Заказ идемпотентен: повторная отправка с тем же ключом не создаёт второй заказ, а отправка с другим содержимым под тем же ключом отклоняется.
- Оплата регистрируется один раз на заказ, ограничение уникальности задано в базе данных.
- API отдаёт `Cache-Control: no-store`; заголовки `Content-Security-Policy`, `Permissions-Policy`, `X-Frame-Options` и `Referrer-Policy` выставляются приложением и Nginx.
- Секреты не хранятся в репозитории: переменные окружения, файлы `.env` и `.secrets/` игнорируются Git.

## Архитектура

```
Браузер
   │
   ├── статика фронтенда ──► Vercel (frontend/dist)  или  Nginx (контейнер frontend)
   │
   └── /api/* ──► Django REST API (serverless на Vercel  или  Gunicorn в контейнере)
                        │
                        └── PostgreSQL (Supabase  или  контейнер db)
```

Фронтенд обращается к API по относительному пути `/api/`. В разработке Vite проксирует `/api` на `http://127.0.0.1:8000` (переменная `ANASYM_API_TARGET`).

## Быстрый старт

Требования: Windows с PowerShell, **Python 3.12**, **Node.js 22** (на Node 24 сборка тоже проходит).

```powershell
# 1. Зависимости бэкенда
python -m venv backend/.venv
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# 2. Зависимости фронтенда
npm --prefix frontend ci

# 3. Настройки: создайте backend/.env и задайте DJANGO_SECRET_KEY
Copy-Item backend/.env.example backend/.env
./backend/.venv/Scripts/python.exe -c "import secrets; print(secrets.token_urlsafe(50))"

# 4. Запуск: миграции, SQLite и демо-данные
./scripts/launch.ps1 -UseSqlite -SeedDemo
```

Если PowerShell блокирует скрипты, запускайте их так: `powershell -ExecutionPolicy Bypass -File ./scripts/launch.ps1 -UseSqlite -SeedDemo`.

После запуска:

- сайт — <http://127.0.0.1:5173>;
- проверка API — <http://127.0.0.1:5173/api/health/> (ответ `{"status": "ok"}`);
- остановка — `./scripts/stop.ps1`;
- журналы — `.secrets/logs/`.

<details>
<summary><b>Параметры <code>launch.ps1</code></b></summary>

| Параметр | Назначение |
| --- | --- |
| `-UseSqlite` | Использовать SQLite (`backend/db.sqlite3`) вместо `DATABASE_URL`. Для разработки. |
| `-SeedDemo` | Заполнить демонстрационными данными. На время запуска выставляется `DEMO_MODE=true`; значение в `backend/.env` не меняется. Существующие пароли не перезаписываются. |
| `-BackendPort`, `-FrontendPort` | Порты Django и Vite, по умолчанию 8000 и 5173. |
| `-PythonExecutable`, `-NodeExecutable` | Пути к интерпретаторам, если их нет в `PATH`. |
| `-PostgresBin` | Каталог `bin` установки PostgreSQL, по умолчанию `C:/Program Files/PostgreSQL/18/bin`. |

Без `-UseSqlite` скрипт требует `DATABASE_URL` в `backend/.env` и подключается к указанной PostgreSQL.

</details>

<details>
<summary><b>Ручной запуск без скриптов</b></summary>

```powershell
# Бэкенд (в backend/.env должно быть USE_SQLITE=true или задан DATABASE_URL)
cd backend
./.venv/Scripts/python.exe manage.py migrate
./.venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000

# Фронтенд (в другом терминале, из корня репозитория)
npm --prefix frontend run dev
```

</details>

<details>
<summary><b>Локально с PostgreSQL</b></summary>

1. Укажите в `backend/.env` строку `DATABASE_URL=postgresql://пользователь:пароль@127.0.0.1:5432/база`. Спецсимволы в пароле кодируйте в URL-формате.
2. Запустите `./scripts/launch.ps1 -SeedDemo`. Если PostgreSQL установлен не по стандартному пути, добавьте `-PostgresBin`.
3. Пользователь базы должен иметь право `CREATEDB`: Django создаёт тестовую базу при запуске тестов.

</details>

## Конфигурация

Переменные читаются из `backend/.env` (шаблон — `backend/.env.example`). Для Docker-развёртывания используется корневой `.env` (шаблон — `.env.example`, создаётся скриптом `scripts/setup-env.ps1`).

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | — | Секретный ключ. **Обязателен.** Вне `DEBUG` должен быть не короче 50 символов. |
| `DEBUG` | `false` | `true` только для разработки. В продакшене запрещён. |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | Домены, которые обслуживает Django. |
| `CSRF_TRUSTED_ORIGINS` | локальные адреса | Origin'ы, с которых принимаются изменяющие запросы. |
| `DATABASE_URL` | — | Строка подключения к PostgreSQL. Если пуста, нужен `USE_SQLITE=true`. |
| `USE_SQLITE` | `false` | Разрешает SQLite только для локальной разработки. |
| `DATABASE_CONN_MAX_AGE` | `60` локально, `0` на Vercel | Время жизни соединения с базой, секунды. |
| `FRONTEND_URL` | `http://localhost:5173` | Адрес фронтенда; используется в ссылках восстановления пароля. |
| `DELIVERY_FEE` | `1500.00` | Стоимость доставки, ₸. |
| `WHOLESALE_MIN_QTY` | `10` | Минимальное количество одного товара в заказе для оптовой цены. |
| `MAX_ORDER_ITEM_QUANTITY` | `99` | Максимум штук одного товара в заказе. |
| `DEMO_MODE` | `false` | Нужен для `seed_demo` и `import_pdf_catalog`. Виден в ответе `/api/settings/` как `demo_mode`. |
| `PASSWORD_RESET_ENABLED` | `true` | Восстановление пароля. Включайте только с настроенной почтой. |
| `EMAIL_BACKEND`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`, `DEFAULT_FROM_EMAIL` | консоль (в отладке) / SMTP | Почта. Консольный backend подходит только для разработки. |
| `IMAGE_ALLOWED_HOSTS` | пусто | Домены, с которых разрешены ссылки на фотографии (через запятую). |
| `CORS_ALLOWED_ORIGINS` | пусто | Origin'ы для отдельно размещённого фронтенда. |
| `SESSION_COOKIE_AGE` | `43200` | Длительность сессии, секунды (12 часов). |
| `COOKIE_SECURE` | `false` локально, `true` иначе | Cookie только по HTTPS. |
| `TRUST_PROXY`, `TRUSTED_PROXY_COUNT` | `false`, `0` | Учёт заголовков прокси. Для одного доверенного прокси — `1`. |
| `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS` | `false`, `0` | HTTPS-редирект и HSTS. Включайте после настройки HTTPS. |
| `DATABASE_URL_TEST` | — | Строка подключения к тестовой PostgreSQL. Имя базы должно содержать `test`. Используется только командой `manage.py test`. |

## Демо-данные и каталог

Начальный каталог лежит в `backend/shop/data/`. Команды выполняются из корня репозитория:

```powershell
./backend/.venv/Scripts/python.exe backend/manage.py seed_catalog        # базовый каталог из JSON
./backend/.venv/Scripts/python.exe backend/manage.py seed_demo           # демо-категории, товары и аккаунты ролей; нужен DEMO_MODE=true
./backend/.venv/Scripts/python.exe backend/manage.py import_pdf_catalog  # импорт из данных PDF-каталога; нужен DEMO_MODE=true
```

- Пароли демо-аккаунтов записываются в `.secrets/demo-accounts.txt`. Файл не попадает в Git.
- Повторный запуск `seed_demo` не меняет существующие пароли.
- Обычные правки (цены, описания, категории, оптовые цены) удобнее делать через кабинет администратора — см. [руководство](docs/admin-guide.md).

## Тестирование и проверки

```powershell
# Бэкенд: 12 тестов параллельности пропускаются на SQLite, поэтому для полной проверки нужен PostgreSQL
./backend/.venv/Scripts/python.exe backend/manage.py test --noinput

# Бэкенд на PostgreSQL (PowerShell; имя базы должно содержать "test")
$env:DATABASE_URL_TEST = 'postgresql://пользователь:пароль@127.0.0.1:5432/anasym_test'
./backend/.venv/Scripts/python.exe backend/manage.py test --noinput
Remove-Item Env:DATABASE_URL_TEST

# Миграции согласованы с моделями
./backend/.venv/Scripts/python.exe backend/manage.py makemigrations --check --dry-run

# Фронтенд: тесты (включая проверку полноты переводов) и сборка с проверкой типов
npm --prefix frontend test
npm --prefix frontend run build
```

Проверка настроек для продакшена (те же переменные, что и в CI):

```powershell
$env:DEBUG='false'; $env:DJANGO_SECRET_KEY='<ключ не короче 50 символов>'; $env:ALLOWED_HOSTS='example.test'
$env:CSRF_TRUSTED_ORIGINS='https://example.test'; $env:FRONTEND_URL='https://example.test'
$env:COOKIE_SECURE='true'; $env:SECURE_SSL_REDIRECT='true'; $env:SECURE_HSTS_SECONDS='31536000'
$env:TRUST_PROXY='true'; $env:TRUSTED_PROXY_COUNT='1'; $env:USE_SQLITE='true'
./backend/.venv/Scripts/python.exe backend/manage.py check --deploy --fail-level WARNING
```

Успешные тесты не заменяют проверку в браузере. Для Docker-стека используйте `docker compose config --quiet` и `docker compose exec backend python manage.py check`.

## Развёртывание

### Vercel и Supabase

`vercel.json` собирает фронтенд (`npm run build --prefix frontend`, каталог `frontend/dist`) и публикует Django как функцию `api/index.py`. Запросы `/api/*` идут в функцию, остальные пути отдаются приложением.

Пошаговая инструкция, переменные окружения, защита таблиц и резервные копии — в [docs/vercel-deployment.md](docs/vercel-deployment.md).

> **Миграции не применяются при деплое.** Сборка Vercel только собирает код. Выполняйте `manage.py migrate` против продакшн-базы отдельно, **до** публикации кода, который от этих миграций зависит. Перед миграцией сделайте резервную копию.

### Собственный сервер: Docker и HTTPS

Нужны Docker с Compose v2 и домен, направленный на сервер (порты 80 и 443 открыты).

```powershell
./scripts/setup-env.ps1      # создаёт .env со случайными секретами; существующий файл не перезаписывается
```

В `.env` задайте `DOMAIN`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS=https://ваш-домен` и `FRONTEND_URL=https://ваш-домен`. Оставьте `FRONTEND_BIND=127.0.0.1` и `DEBUG=false`. Затем:

```powershell
docker compose -f docker-compose.yml -f deploy/compose.https.yml up -d --build
```

Сервисы: `db` (PostgreSQL 17), `backend` (Gunicorn, миграции при старте), `frontend` (Nginx). Caddy получает сертификат и проксирует запросы в Nginx.

Для локальной проверки Docker-стека без HTTPS: `docker compose up -d --build`, сайт — <http://localhost:8080>. Демо-данные в этом режиме: в корневом `.env` задайте `DEMO_MODE=true`, затем выполните `docker compose exec --user root backend python manage.py seed_demo`.

Данные PostgreSQL хранятся в томе `postgres_data`: `docker compose down` их сохраняет, `docker compose down -v` удаляет.

### Перед коммерческим запуском

- Подтвердить товары, цены, вес, состав и аллергены.
- Проверить адрес, контакты, зону и стоимость доставки.
- Утвердить правила отмены и возврата, реквизиты продавца и тексты согласий (оферта, политика конфиденциальности).
- Настроить SMTP и проверить восстановление пароля, затем включить `PASSWORD_RESET_ENABLED=true`.
- Установить `DEMO_MODE=false` и заменить демонстрационное наполнение.
- Проверить резервные копии на тестовой базе (см. ниже).

## Резервные копии

Скрипты `scripts/backup.ps1` и `scripts/restore.ps1`. Порядок действий, частота и проверка восстановления — в [docs/backup-restore.md](docs/backup-restore.md). Восстановление сначала проверяется в отдельной базе, а не в рабочей.

## Ограничения и статус проекта

**Статус:** MVP. Функциональность протестирована, но публичный запуск с реальными клиентами требует закрытия задач из [дорожной карты](PRODUCTION_ROADMAP.md): подтверждённые данные, бэкапы продакшн-базы, решения по персональным данным и проверку на рабочей инфраструктуре.

**Известные ограничения:**

- Онлайн-оплата не подключена, принимаются только наличные при получении.
- Нет учёта остатков: доступность товара задаётся вручную.
- Покупатель не может отменить заказ сам; отмену выполняет администратор.
- Список заказов для администратора не постраничный.
- Оптовые цены требуют одобрения заведения администратором; автоматической проверки реквизитов нет.
- Тексты оферты и политики конфиденциальности требуют юридической проверки.

## Соглашения о разработке

- Коммиты оформляются по Conventional Commits: `feat(...)`, `fix(...)`, `test(...)`, `docs(...)`, `chore(...)`.
- Исправление сопровождается тестом, который падает до исправления и проходит после него.
- Секреты, пароли и строки подключения передаются только через переменные окружения. В тестах допустимы явные заглушки с пометкой `test-only`.
- Изменения схемы базы — только через миграции Django; миграции проверяются `makemigrations --check`.

## Лицензия

Лицензия не выбрана. До её появления все права на код и материалы принадлежат владельцу проекта.
